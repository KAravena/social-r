# Social R v0.3.7 — Console Layout + Grading State Fix Report

## 1. Executive Summary

In Social R v0.3.7, two critical bugs were resolved:

1. **Native R Output Positioning (Bug A)**: The native output generated by Quarto Live (`.cell-output-container`) was relocated physically **BELOW** the `"R Console"` header panel (`.sr-console-header`). The false empty console body (`#sr-console-body`) was completely removed from the template hierarchy. Native outputs now pass strict geometric bounding box verification (`outputRect.top > consoleHeaderRect.bottom`).
2. **Grading State & Stale Feedback Invalidation (Bug B)**: Stale feedback cards (`#sr-feedback-card-${exerciseId}`) in the left panel are now immediately hidden whenever the student modifies their code (`currentCode !== lastSubmittedCode`). The **Ejecutar** (Run) button remains purely exploratory and does not trigger grading or show feedback cards in the left panel. **Enviar respuesta** (Submit) evaluates the active code and renders pedagogical feedback. Exercise 4 (`intro-r-01-003: 'Números vs Texto'`) diagnostic coverage was fully verified across string assignments, incorrect numeric values, missing target objects, and correct numeric assignments.

---

## 2. Root Cause Analysis

### Bug A: Native Output Rendering Outside Console Boundary
- **Root Cause**: Quarto Live mounts `.cell-output-container` inside the exercise card container `.sr-editor-panel` / `.card.exercise-editor`. In v0.3.6, a dummy console body (`#sr-console-body`) existed below `.sr-console-header`, but native output was rendered above the header by default flex ordering.
- **Solution**: Removed `#sr-console-body`. Restructured exercise template hierarchy in `engine/generator/build.py` placing `.sr-console-header` directly below `.sr-editor-toolbar`. Applied absolute CSS positioning in `css/editor-console.css` (`position: absolute; top: 332px; left: 0; right: 0; bottom: 0;`), placing `.cell-output-container` geometrically **BELOW** `.sr-console-header` (header top: `346px`, bottom: `381px`, output top: `413px`).

### Bug B: Stale Feedback Persistence & WebR Grader Scope Initialization
- **Root Cause 1**: Feedback cards retained old evaluation messages when students edited their answer after submitting.
- **Root Cause 2**: WebR evaluation inside Quarto Live expected `.checker_args` and `options(webr.exercise.checker)` to be initialized in the R environment and WebR grader context.
- **Solution**:
  - Implemented `lastSubmittedCode` tracking and `invalidateFeedbackIfStale(exerciseId)` in `QuartoLiveAdapter` (`js/platform/quarto-live-adapter.js`).
  - Attached document-level `input` event listener in `SocialREngine` (`js/social-r.js`) to trigger feedback invalidation instantly upon typing.
  - Initialized `options(webr.exercise.checker)` in WebR before calling `WebRGrader.gradeExercise()`, ensuring diagnostic evaluation runs cleanly in the cell's environment.
