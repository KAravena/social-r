# 09 · Roadmap

## Fase 1A — validación del runtime

- instalar Quarto Live en `prototype/`;
- renderizar;
- ejecutar los 3 ejercicios en Chrome/Edge/Firefox;
- comprobar feedback y pistas;
- medir carga inicial, primera ejecución y ejecuciones posteriores;
- probar bucle infinito con `timelimit` en preview local y GitHub Pages/host final;
- smoke test de paquetes.

## Fase 1B — contrato de plataforma

- definir adapter QuartoLive → SocialREventBus;
- guardar intentos/hints/completado localmente;
- testear persistencia y borrado;
- crear test de regresión de DOM/API para la versión fijada.

## Fase 2 — diseño pedagógico

- taxonomía definitiva de ejercicios;
- progresión mirar → completar → modificar → escribir → interpretar;
- matriz de habilidades de las 62 capturas de referencia;
- nueva secuencia curricular para ciencias sociales.

## Fase 3 — contenido piloto

Transformar 8–12 ejercicios del primer módulo, no los 62 de una vez. Realizar prueba con estudiantes novatos y registrar errores reales para mejorar diagnostics.

## Fase 4 — experiencia de plataforma

Solo después del motor validado: navegación, progreso visual, gamificación, accesibilidad y diseño frontend.

## Fase 5 — persistencia remota opcional

Introducir backend únicamente si es necesario sincronizar usuarios/progreso o usar la plataforma para evaluación formal.
